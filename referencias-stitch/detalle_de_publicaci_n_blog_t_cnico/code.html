“Las interfaces táctiles en navegadores modernos frecuentemente fallan no por limitaciones de GPU, sino por contención de ciclo de reloj en el Main Thread durante eventos de puntero. Exploramos cómo delegar el solucionador de ecuaciones diferenciales a un worker en segundo plano para garantizar inercia física sin caídas de cuadro.”

01 //

El dilema del fotograma y la cadencia táctil

El ojo humano entrenado y la respuesta neuromuscular operan bajo una expectativa táctil estricta: cuando el pulgar se desliza sobre una pantalla con tasa de refresco adaptativa ProMotion (120Hz), cualquier desfase temporal superior a los 8.33 milisegundos se interpreta instantáneamente como pesadez mecánica o fricción artificial.

En las aplicaciones web tradicionales, el bucle requestAnimationFrame compite directamente contra la hidratación de componentes, deserialización de payloads JSON y cálculos de layout. Cuando se suscita un recolector de basura (GC Pause), el hilo colapsa momentáneamente, precipitando el fotograma a 33.3ms — una caída de 120 FPS a 30 FPS perceptible en milisegundos críticos.

02 //

Modelado matemático de amortiguamiento crítico

A diferencia de las curvas cúbicas bézier predefinidas (cubic-bezier()), los sistemas físicos basados en resortes retienen el momento y la inercia vectorial del usuario al soltar el puntero. La ecuación diferencial lineal de segundo orden de Hooke-Stokes describe el comportamiento cinemático:

m · x’’(t) + c · x’(t) + k · x(t) = 0

Donde m es la masa inercial, c el coeficiente de disipación viscoplástica y k la rigidez elástica (tension).

Para resolver la ecuación en tiempo real dentro del ciclo de vida del navegador, delegamos el solver numérico Runge-Kutta de 4to orden (RK4) a un Web Worker dedicado, el cual posee la transferencia exclusiva de un lienzo de visualización vía canvas.transferControlToOffscreen().

spring-solver.worker.ts — TypeScript / OffscreenCanvas 
interface SpringConfig {
  stiffness: number;   // k: constante elástica (ej. 170)
  damping: number;     // c: coeficiente amortiguador (ej. 26)
  mass: number;        // m: masa del elemento (ej. 1.0)
}

export class OffscreenSpringIntegrator {
  private ctx: OffscreenCanvasRenderingContext2D;
  private pos = 0;
  private vel = 0;
  private target = 0;

  constructor(canvas: OffscreenCanvas, private cfg: SpringConfig) {
    this.ctx = canvas.getContext('2d')!;
  }

  public update(dt: number): void {
    // Integración semi-implícita Euler-Verlet a 120 FPS
    const force = -this.cfg.stiffness * (this.pos - this.target);
    const dampingForce = -this.cfg.damping * this.vel;
    const accel = (force + dampingForce) / this.cfg.mass;

    this.vel += accel * dt;
    this.pos += this.vel * dt;

    this.render();
  }

  private render(): void {
    this.ctx.clearRect(0, 0, 800, 600);
    this.ctx.translate(this.pos, 0);
    // Blit directo sin roundtrips con el Main Thread
  }
}
