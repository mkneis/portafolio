Aether UI

Micro-framework de física elástica y gestualidad inercial para interfaces táctiles de alta frecuencia (120Hz+).

Aether UI resuelve la pérdida de fotogramas en pantallas táctiles de alta densidad durante manipulaciones espaciales continuas. Al desacoplar el cálculo inercial del ciclo de reconciliación DOM mediante un hilo de ejecución aislado (Offscreen Worker) y transformaciones matriciales directas a GPU, el framework asegura una experiencia táctil indistinguible de una superficie analógica.

01 / El Desafío Fundamental

Por qué las interfaces táctiles web tartamudean a 120Hz

El modelo tradicional de interacción en la web vincula los eventos táctiles (`touchstart`, `touchmove`) al hilo de ejecución primario (Main Thread). Cuando la lógica de aplicación realiza trabajo de renderizado, cálculo de layout o recolección de basura (GC), la tasa de respuesta se fragmenta, introduciendo una latencia física perceptible por el usuario.

Arquitectura Convencional warning

Main Thread Bottleneck

Las librerías clásicas serializan coordenadas a través del puente de eventos del navegador, mutan el DOM o el Virtual DOM en cada tick y compiten por ciclos de cómputo con la lógica del negocio.

✕ Touch Event disparado en Main Thread
✕ Serialización y cálculo de React/Vue diff
✕ Layout Thrashing & GC Stutter (16ms+)
Resultado: Caídas a 45-60 FPS en pantallas ProMotion de 120Hz.
Arquitectura Aether UI bolt

Worker Desacoplado & Direct GPU

Aether aísla el cálculo de vectores inerciales en un Web Worker en segundo plano que comunica coordenadas mediante SharedArrayBuffer, aplicando transformaciones directamente al compositor sin tocar el Main Thread.

✓ Direct Pointer Stream a Offscreen Core
✓ Shared Memory Zero-Copy Interpolation
✓ Transform 3D commit a GPU compositor (<1.5ms)
Resultado: Fluidez cristalina y sostenida a 120Hz bajo cualquier carga.

// aether-core/src/solver.rs - Rust WASM Core
use wasm_bindgen::prelude::*;

#[wasm_bindgen]
pub struct SpringSolver {
    stiffness: f32,
    damping: f32,
    mass: f32,
    velocity: f32,
}

#[wasm_bindgen]
impl SpringSolver {
    pub fn step(&mut self, dt: f32, displacement: f32) -> f32 {
        let spring_force = -self.stiffness * displacement;
        let damping_force = -self.damping * self.velocity;
        let acceleration = (spring_force + damping_force) / self.mass;
        self.velocity += acceleration * dt;
        self.velocity
    }
}
